A browser can't touch the first one at all — scanning a 400 GB parquet lake needs a query engine, not fetch(). That's why this page has a Python kernel attached.

One Python run per city: DuckDB scans Overture on S3, numpy + a priority-flood fill compute the minimum sea level that reaches each cell, and the terrain mesh + satellite texture are mosaicked into single images.

It scans only the row groups whose bounding box overlaps the AOI — a few hundred MB touched out of hundreds of GB.
The flood model isn't elevation < level — that's what a no-kernel page could do. Python runs a connectivity fill from the sea:
water has to get there — a basin stays dry until a connected path from the sea exists. Toggle to compare.
model: bathtub + connectivity — levees thinner than a grid cell vanish, so New Orleans floods sooner here than its real defenses allow.
Python doesn't return maps or answers to one question — it returns grids and curves: the flood level of every cell and building. The browser holds them in typed arrays, so the slider is a pure client-side threshold — deck.gl re-colors 100k+ cells per frame, zero Python calls per drag.

The backend is two ordinary Python files with a main(). The whole integration is one call:
const r = await fused.runPython(
  "./flood_mask.py", { xmin, ymin, xmax, ymax, barriers });
Results cache to disk — the first visitor pays the S3 scan, everyone after gets it in milliseconds. No server to deploy, no build step: edit the .py, reload the page.
