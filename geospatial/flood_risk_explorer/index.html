Behind the scenes

This whole app is one HTML file with a Python kernel attached — Fused Render runs flood_mask.py and overture_stats.py right next to the page. Ask Claude for a standalone HTML flood map and you get a browser sandbox: no DuckDB, no numpy, no S3. These are the actual arrays Python handed this page for the city you have open:

This exact query runs in the Python kernel next to this page — DuckDB reading Overture's GeoParquet on S3 directly, no download, no database server. Only the row groups overlapping this AOI are touched, and the result is cached to disk for the next visitor.
the whole integration — hover a piece
const r = await fused.runPython("./flood_mask.py", { xmin, ymin, xmax, ymax, barriers });
r.elev_b64     // int16 terrain grid — water-clamped, dikes burned in
r.flood_b64    // int16 "floods at" grid — one priority-flood, done once
r.terrain_png + r.texture_jpg    // 3D mesh + satellite skin, mosaicked in Python

const s = await fused.runPython("./overture_stats.py", { xmin, ymin, xmax, ymax });
s.buildings    // every footprint + height + the level that floods it, via DuckDB
